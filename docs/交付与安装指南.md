# 交付与安装指南 —— 从提交代码到手机装上 App

> 本文覆盖「推代码 → GitHub Actions 自动跑测试并打出 IPA → 下载 → 签名装到 iPhone」的完整链路。
> 面向第一次操作的人，每条命令都可直接复制。工程根目录：`ReadingApp/`（与 `ReadingApp.xcodeproj` 同级）。

> **⚠️ 当前仓库的 `ci.yml` 是「签名版」**：产物为已签名的 Development IPA，下载后可**直接**装到 UDID 已登记的设备，不需要 Sideloadly。
> 签名的准备与排错请看 **[签名打包与证书配置.md](签名打包与证书配置.md)**。
> 本文 §四（Sideloadly）适用于**未签名构建**——即没有开发者账号、或你触发的是仓库内置的备用流水线 `CI (Unsigned)`（`ci-unsigned.yml`，仅手动触发）；有证书且跑的是签名版 `CI` 时不必看那一节。

## 〇、一页速览

```bash
# 1. 首次推送到 GitHub（仓库已在网页端建好、且为空仓库）

git branch -M main

```

推送完成 → 打开 `https://github.com/<你的账号>/<仓库名>/actions` → 等绿灯 → 在该次运行页面底部 **Artifacts** 下载 `ReadingApp-unsigned-ipa`。

## 一、首次把代码推到 GitHub

### 1.1 网页端建仓库

1. 打开 <https://github.com/new>。
2. `Repository name` 填仓库名（建议 `ReadingApp`）。
3. 可见性按需选 `Public` / `Private`（见 §1.5 的费用提示）。
4. **不要勾选** `Add a README file`、`.gitignore`、`license`——本地已有这些文件，勾选会导致首次 push 冲突。
5. 点 `Create repository`，复制页面上的仓库地址（`https://github.com/xxx/ReadingApp.git`）。

### 1.2 本地初始化并提交

在工程根目录（能看到 `ReadingApp.xcodeproj` 的那一层）执行：

```bash
git init
git add -A
git status --short | head -20        # 先确认没有把 build/、*.xcresult 加进来
git commit -m "chore: P0-P5 全阶段交付（小说+漫画阅读器 / 同步 / 无障碍 / 上架材料 / CI 打包）"
git branch -M main
git remote add origin https://github.com/<你的账号>/<仓库名>.git
git push -u origin main
```

> **Push 认证**：GitHub 已不支持账号密码。HTTPS 方式需要 Personal Access Token（`Settings → Developer settings → Personal access tokens → Tokens (classic)`，勾 `repo` 权限），在提示输入密码时粘贴 token；或改用 SSH（`git remote set-url origin git@github.com:...`）。

### 1.3 推送前必查三项

这三项任一缺失，云端构建会直接失败：

```bash
# ① 共享 scheme 必须在版本库里（xcuserdata 被忽略，scheme 不在里面）
git ls-files ReadingApp.xcodeproj/xcshareddata
# 期望输出：ReadingApp.xcodeproj/xcshareddata/xcschemes/ReadingApp.xcscheme

# ② 工作流文件必须在版本库里
git ls-files .github/workflows
# 期望输出：.github/workflows/ci.yml

# ③ 验收脚本必须在版本库里（CI 会直接调用）
git ls-files scripts
# 期望输出：acceptance.sh / check_project.py / coverage_report.py / pick_simulators.py / run_tests.sh
```

三项都齐了再 push。

### 1.4 推送后确认

```bash
git log --oneline -3
git remote -v
```

浏览器打开仓库首页，应能看到 `ReadingApp/`、`ReadingAppTests/`、`ReadingApp.xcodeproj/`、`.github/`、`scripts/`、`docs/`。

### 1.5 费用提示（Private 仓库必读）

- **Public 仓库**：GitHub Actions 的 macos-14 标准 runner 不计费，随便跑。
- **Private 仓库**：从账户附赠额度里扣分钟数，且 **macOS runner 按 10 倍计费**（跑 10 分钟扣 100 分钟）。一次完整流水线约 8–15 分钟，折合约 80–150 分钟额度。
- 制品保留 30 天是本文配置值，若账户套餐上限更低会被截断。

## 二、触发工作流

### 2.1 三种触发方式

| 方式 | 操作 | 何时用 |
| --- | --- | --- |
| push 到 main | `git push` | 日常提交，最常用 |
| 开 PR | 在网页端 `Pull requests → New pull request`，源分支推上去即触发 | 改完想先看测试结果再合并 |
| 手动 | 仓库页 `Actions → 左侧 CI → 右侧 Run workflow → 分支选 main → Run workflow` | 不改代码、只想重打一个包 |

> 手动触发（`workflow_dispatch`）是「只想要一个新 IPA」时最省事的方式，不会产生空提交。

### 2.2 看进度

1. 打开 `https://github.com/<账号>/<仓库名>/actions`。
2. 左侧点 `CI`，右侧点最新一条运行记录。
3. 点 job 名 **`测试 · 覆盖率 · IPA 打包`**，展开 12 个步骤看实时日志。

各步骤正常耗时（macos-14，含 SPM 冷启动）：

| 步骤 | 首次 | 有缓存 |
| --- | --- | --- |
| 选择 Xcode / 校验 iOS 17 | 10 s | 10 s |
| 缓存 SPM 与 DerivedData | 20–60 s | 5–15 s |
| 工程合规校验 | 2 s | 2 s |
| 全量测试 + 覆盖率（双目的地） | 4–7 min | 2–4 min |
| Release Archive | 2–4 min | 1–3 min |
| 导出 IPA | 5 s | 5 s |
| 上传制品 | 10–30 s | 10–30 s |

### 2.3 跑完看什么

- 顶部绿勾 = 全绿；红叉 = 有步骤失败（跳到 §5 排查）。
- 页面底部 **Summary** 区有自动写入的「验收与打包结果」表 + 覆盖率报告 + 合规校验清单。

## 三、下载 IPA

### 3.1 位置

在该次运行页面**最下方**的 `Artifacts` 区域，有三个制品：

| 制品名 | 内容 |
| --- | --- |
| `ReadingApp-development-ipa`（签名版）／`ReadingApp-unsigned-ipa`（未签名版） | **IPA 安装包**（你要的） |
| `ReadingApp-dSYM` | 调试符号，崩溃日志符号化用（普通使用可不下载） |
| `build-reports`（签名版）／`acceptance-reports`（未签名版） | 覆盖率报告 + 工程合规校验报告 + 签名信息 |

### 3.2 关键细节

- GitHub 会把 artifact **再包一层 zip**：下载得到 `ReadingApp-development-ipa.zip`，解压后才是 `ReadingApp-development-0.1.0-1.ipa`。
- 文件名里的 `0.1.0-1` 是 `CFBundleShortVersionString-CFBundleVersion`，方便区分不同构建。
- **必须登录 GitHub** 才能下载；手机浏览器上 artifact 下载经常失败，用电脑。
- **30 天后自动过期**，过期后需重新触发一次构建。
- 换台电脑下载：直接在新机器登录 GitHub 下载即可，制品存在 GitHub 侧。

### 3.3 校验一下再装（可选但建议）

Windows 上解压后，把 `.ipa` 当 zip 打开（右键 → 用压缩软件打开，不要解压），确认存在：

```
Payload/ReadingApp.app/ReadingApp        ← 主可执行文件（无扩展名）
Payload/ReadingApp.app/Info.plist
```

`Payload/ReadingApp.app/` 里没有 `_CodeSignature/` 目录是**正常的**——这就是「未签名包」，接下来由 Sideloadly 用你自己的 Apple ID 重新签名。

## 四、Windows 安装 IPA（未签名构建适用）

> **本节只适用于未签名 IPA。** 当前仓库的签名版工作流产出的 `ReadingApp-development-ipa` 已由云端证书签好，安装改用：Mac 用 Apple Configurator 2 / Xcode，Windows 用 iMazing / 3uTools（保留原签名）。
> 只有在「没有开发者账号」或「你另存了未签名工作流」时，才需要走下面的 Sideloadly 重签流程。

### 4.1 先理解一件事

本节假设 CI 产出的是**未签名 IPA**。iOS 只接受「有签名」的 App，所以中间必须有一个工具用**你自己的 Apple ID** 给它签一次名——Sideloadly 就是干这个的。免费 Apple ID 签出来的证书 **7 天过期**，这是 Apple 的规则，不是工具限制。

### 4.2 准备清单

| 项目 | 说明 |
| --- | --- |
| Windows 电脑 | Win10 / Win11 均可 |
| iTunes | **必须从 Apple 官网下载**（<https://www.apple.com/itunes/>），**不要装 Microsoft Store 版**——Store 版不装 `Apple Mobile Device Support` 驱动，Sideloadly 认不到手机 |
| 数据线 | 有线连接，别用只能充电的劣质线 |
| Apple ID | 普通免费账号即可，**无需**开发者账号、无需付费 |
| iPhone | iOS 17 建议；系统版本越新越要求「开发者模式」 |
| 网络 | 签名时需访问 Apple 服务器校验账号 |

> 若 Sideloadly 提示缺少组件，按官网 FAQ 补装 `iCloud for Windows`（同样从 Apple 官网下载）。

### 4.3 安装 Sideloadly

1. 打开 <https://sideloadly.io/>。
2. 点 `Download for Windows`（文件名形如 `SideloadlySetup.exe`）。
3. 双击安装，一路 `Next`；如杀软拦截，选择「允许/仍要运行」（该工具需调用 Apple 驱动，误报常见）。
4. 首次启动若提示安装 `Apple Mobile Device Support`，按提示装。

### 4.4 手机端准备

1. 数据线连接电脑，iPhone 上点「**信任此电脑**」并输入锁屏密码。
2. iPhone：`设置 → 隐私与安全性 → 开发者模式` → 打开 → **重启手机** → 重启后再次确认开启。
   （iOS 16 及以上必须开，否则装完点不开，提示「无法验证 App」。）
3. 记下手机的 UDID（可选）：Sideloadly 顶部会显示设备名，识别到即连接成功。

### 4.5 签名安装步骤

1. 打开 Sideloadly。
2. `IPA` 一栏：把解压出来的 `ReadingApp-unsigned-0.1.0-1.ipa` **拖进窗口**（或点该栏右侧图标选择文件）。
3. `Apple ID` 一栏：填你的 Apple ID 邮箱。
4. （推荐）点 `Advanced Options` / 密码框旁选项，改用 **App 专用密码**：
   打开 <https://appleid.apple.com> → `登录与安全 → App 专用密码 → 生成`，把生成的 16 位密码填进 Sideloadly 密码框。这样不必把主密码交给第三方工具。
5. （可选）如需与别人区分，展开 `Advanced Options`，把 `Bundle ID` 改成自己的，例如 `com.yourname.readingapp`。
   免费账号每个 Bundle ID 会被占用，撞车会报「An App ID with Identifier is not available」。
6. 点 **`Start`**。
7. 等待进度条走完（首次 1–3 分钟，含向 Apple 申请证书），出现 `✅ Done`。
8. iPhone 上：`设置 → 通用 → VPN 与设备管理 → 开发者 App → 点你的 Apple ID → 信任`。
9. 回到桌面，App 图标已出现，可以打开。

### 4.6 7 天重签说明（必读）

**为什么会过期**：免费 Apple ID 签发的描述文件有效期 **7 天**。到期后 App 不会消失，但**双击闪退 / 提示「不再可用」**。

**到期怎么办**：重新用 Sideloadly 装一次即可（IPA 文件还在就直接再 `Start` 一次）。同 Bundle ID 覆盖安装通常**保留 App 内的书架与阅读进度**，但这是「通常」不是保证，重要进度建议先用 App 内的 WebDAV 同步备份一份。

**免费账号的其他限制**：

| 限制 | 说明 |
| --- | --- |
| 有效期 7 天 | 到期需重签 |
| 同时最多 3 个自签 App | 装满后需先删一个 |
| 每 7 天最多 10 个 App ID | 反复改 Bundle ID 会消耗配额 |
| 无法推送通知、部分后台能力受限 | 本项目核心功能（阅读 / 下载 / 同步）不受影响 |

**不想每 7 天手动重签的三条路**：

| 方案 | 成本 | 效果 |
| --- | --- | --- |
| **AltStore + AltServer** | 免费 | 手机与电脑同一 Wi-Fi 时自动后台续签，省去手动操作；仍需电脑常开 |
| **Apple Developer Program** | $99/年 | 证书 1 年有效，可上 TestFlight 分发，最省心 |
| **企业证书 / 共享签名** | 灰色 | 随时可能被封，不建议 |

> 本项目自身不涉及任何签名服务，以上均为通用 iOS 侧载知识。

### 4.7 安装阶段常见报错

| 报错 | 原因 | 处理 |
| --- | --- | --- |
| `Could not find Apple Mobile Device Support` | 装了 Microsoft Store 版 iTunes | 卸载后装 Apple 官网版 iTunes |
| `Failed to obtain a signing certificate` / `Wrong username or password` | 密码错，或开了双重认证却用了主密码 | 用 App 专用密码（§4.5 第 4 步） |
| `An App ID with Identifier "..." is not available` | Bundle ID 被别人/自己占用 | `Advanced Options` 里改一个独有的 Bundle ID |
| 装完点开闪退 / 「无法验证 App」 | 没开开发者模式，或没信任证书 | 按 §4.4 第 2 步 + §4.5 第 8 步补做 |
| 卡在 `Installing...` 不动 | 数据线/驱动问题 | 换线换 USB 口，重启 Apple Mobile Device Service（`services.msc`） |

## 五、三个最常见的打包失败原因与排查

### 失败 ①：签名类错误 —— `requires a development team` / `No profiles were found`

**日志特征**

```
Signing for "ReadingApp" requires a development team. Select a development team
in the Signing & Capabilities editor.
error: No profiles for 'com.example.ReadingApp' were found
```

**原因**：Archive 阶段签名没被真正关掉。常见于三类操作：命令行把 `CODE_SIGNING_ALLOWED=NO` 写成了 `-CODE_SIGNING_ALLOWED NO`（位置/形式错）；手工改过 workflow 用了 `-exportArchive`；项目里的 Signing 配置被改成 Manual 并写了 Team 占位。

**排查**

```bash
# 1) 本地原样复现（macOS）
xcodebuild archive -project ReadingApp.xcodeproj -scheme ReadingApp \
  -configuration Release -destination 'generic/platform=iOS' \
  -archivePath build/ReadingApp.xcarchive \
  CODE_SIGNING_ALLOWED=NO CODE_SIGNING_REQUIRED=NO \
  CODE_SIGN_IDENTITY="" CODE_SIGN_ENTITLEMENTS="" DEVELOPMENT_TEAM=""

# 2) 确认签名设置最终生效值（应全为空/NO）
xcodebuild -showBuildSettings -project ReadingApp.xcodeproj -scheme ReadingApp \
  -configuration Release | grep -E "CODE_SIGN|DEVELOPMENT_TEAM|PROVISIONING"
```

**修法**：确保 `CODE_SIGNING_ALLOWED=NO` 等参数作为 **build settings 放在 `xcodebuild` 命令末尾**（不是 `-` 开头的 flag）；不要同时使用 `-exportArchive`（它必须有证书）。

---

### 失败 ②：找不到 scheme / 找不到目的地 —— `does not contain a scheme named` / `Unable to find a destination`

**日志特征**

```
xcodebuild: error: The project 'ReadingApp' does not contain a scheme named "ReadingApp".
```

```
Unable to find a destination matching the provided destination specifier
```

**原因**：scheme 没进版本库（Xcode 在 `xcuserdata/` 里生成的私 scheme 被 `.gitignore` 忽略，只有 `xcshareddata/` 的才算共享）；或 runner 上没有 iOS 17 runtime / 模拟器名硬编码不匹配。

**排查**

```bash
git ls-files ReadingApp.xcodeproj/xcshareddata
# 没有输出 = scheme 没提交，必须补上
```

```bash
# 本地确认工程能列出该 scheme
xcodebuild -list -project ReadingApp.xcodeproj
```

**修法**：确认 `ReadingApp.xcodeproj/xcshareddata/xcschemes/ReadingApp.xcscheme` 已提交。若确实丢失：Xcode 打开工程 → `Product → Scheme → Manage Schemes` → 勾选 `Shared` → 提交该文件。CI 里目的地使用自动挑选（`scripts/pick_simulators.py`），不要硬编码 `OS=17.0` 这类会随镜像变化的字符串。

---

### 失败 ③：测试/合规先失败，导致打包被跳过 —— step 变灰 + `No files were found`

**日志特征**

- `全量单元测试 + 覆盖率 + 合规` 步骤红叉，后面 `Archive` / `导出 IPA` 显示 **skipped**；
- 或 IPA 上传步骤报 `No files were found with the provided path: build/ReadingApp-unsigned-*.ipa`。

**原因**：`acceptance.sh` 内部任一环失败即中断——工程合规校验不过（新增 Swift 文件忘了注册进 target）、iPad 模拟器缺失、覆盖率低于门槛、或某个单测挂了。

**排查（按顺序）**

```bash
# 1) 本地跑一遍，最快定位到 4 个子环节的哪一个
bash scripts/acceptance.sh

# 2) 只看工程合规（最容易出错的一项）
python3 scripts/check_project.py

# 3) 只看测试
xcodebuild test -project ReadingApp.xcodeproj -scheme ReadingApp \
  -destination 'platform=iOS Simulator,name=iPhone 15' -quiet
```

**修法**：按失败点处理——未注册文件用 Xcode `Add Files to ReadingApp` 勾选 target；覆盖率不达标就补测试或调 `COVERAGE_THRESHOLD`；单测失败看 `acceptance-reports` artifact 里的 `Result-*.xcresult`。

---

### 其他常见错误速查

| 日志 | 原因 | 处理 |
| --- | --- | --- |
| `Could not resolve package dependencies` / `Failed to clone repository` | SPM 网络抖动或缓存损坏 | 重跑一次；仍失败则删除 Actions 里的缓存（`Caches` 页面）后重跑 |
| `未找到 iOS 17.x 模拟器 runtime` | 镜像默认 Xcode 不是 15.4 | 检查 `选择 Xcode 15.4` 步骤日志；确认 `/Applications/Xcode_15.4.app` 存在 |
| `The job running on runner ... has exceeded the maximum execution time` | 缓存全冷 + 网络慢 | 已设 `timeout-minutes: 60`，通常不会触发；重跑即可 |
| Artifacts 区域空白 | 上传步骤失败或任务在测试阶段就红了 | 看该次运行是否走到「上传 IPA 制品」这一步 |
| 下载的 zip 里没有 ipa | 下错制品（下成了 dSYM） | 认准 `ReadingApp-unsigned-ipa` |

## 六、交付结论

**本项目 P0–P5 全阶段开发与云端打包链路已全部闭环。**

- **开发侧**：P0 基础设施 → P1 小说阅读器/书架/书源 → P2 下载管理 + 后台续传 → P3 漫画阅读器/容器/缓存 → P4 WebDAV 同步 + 双体系收口 → P5 iPad 适配/无障碍/上架材料，六阶段全部交付并通过验收，单测覆盖解析、网络、下载、同步、布局判定与无障碍文案，全部零网络可重复执行。
- **交付侧**：`push` 即触发「工程合规校验 → iPhone/iPad 双目的地全量测试 → 覆盖率统计 → Release Archive → 导出未签名 IPA → 上传制品（30 天）」全自动链路，无需本地 Mac、无需开发者账号。
- **后续工作方式**：**改代码 → `git push` → Actions 等绿灯 → 下载 `ReadingApp-unsigned-ipa` → Sideloadly 签名安装**。不再需要手动执行任何构建命令。

唯一需要周期性操作的只有一件事：免费 Apple ID 的签名 **7 天到期后重签一次**（§4.6）。这是 Apple 的账号规则，与本项目实现无关。
