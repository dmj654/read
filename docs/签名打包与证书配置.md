# 签名打包与证书配置指南（Development IPA）

> 目标：把 Apple 开发者证书（.p12）与描述文件（.mobileprovision）存进 GitHub Secrets，由 Actions 自动导入钥匙串、完成签名，产出**可直接安装到已注册设备**的 Development IPA。
> 对应工作流：`.github/workflows/ci.yml`（job 名 `测试 · 签名 · 导出 IPA`）。

---

## 〇、先确认三件事

| 项目 | 要求 |
| --- | --- |
| 账号 | **Apple Developer Program 付费账号**（$99/年）。免费账号的描述文件只有 7 天、且需经 Xcode 即时生成，无法稳定用于 CI |
| 证书类型 | **Apple Development**（不是 Apple Distribution） |
| 描述文件类型 | **iOS App Development**，且**包含目标 iPhone 的 UDID** |

> Development 签名的 IPA 只能装到「描述文件里登记过 UDID」的设备上。没登记的设备装不上，这不是签名错误，是 Apple 的规则。

---

## 一、需要准备的 4 个值

| Secret 名 | 内容 | 从哪来 |
| --- | --- | --- |
| `BUILD_CERTIFICATE_BASE64` | `.p12` 文件转成 Base64 | 钥匙串访问导出（§二） |
| `P12_PASSWORD` | 导出 p12 时设置的密码 | 你自己设的 |
| `PROVISIONING_PROFILE_BASE64` | `.mobileprovision` 转成 Base64 | 开发者门户下载（§三） |
| `TEAM_ID` | 10 位 Team ID | 开发者门户 Membership（§一.1） |

可选（按需）：

| Secret 名 | 用途 |
| --- | --- |
| `BUNDLE_ID` | 覆盖工程里的 Bundle ID（如你的 App ID 不是 `com.example.ReadingApp`） |
| `PROFILE_SPECIFIER` | 覆盖自动解析的描述文件名（名称含中文/特殊字符时更稳） |

### 1.1 拿 Team ID

1. 打开 <https://developer.apple.com/account>。
2. 左侧 `Membership details`。
3. 复制 **Team ID**（10 位，形如 `A1B2C3D4E5`）。

---

## 二、从 Mac 导出 .p12 证书

> 必须在**当初生成该证书的那台 Mac** 上导出，或在该 Mac 的钥匙串里已存在「证书 + 私钥」配对。只有 `.cer` 没有私钥是无法签名的。

### 2.1 确认证书存在

1. 打开「钥匙串访问」（Spotlight 搜 `Keychain Access`）。
2. 左上角选 `登录` 钥匙串 → 类别选「**我的证书**」。
3. 找到形如 **`Apple Development: 你的名字 (A1B2C3D4E5)`** 的条目。
   - 前面有展开三角、能展开出私钥的，才是完整的（证书 + 私钥）。
   - 如果只有 `Apple Development` 但没私钥：说明证书是在别的机器上生成的，需要那台机器导出，或重新生成一份。

### 2.2 导出

1. 右键该条目 → **导出「Apple Development: ...」**。
2. 格式选 **个人信息交换 (.p12)**。
3. 存为 `cert.p12`，**设置一个密码**（记住它，就是 `P12_PASSWORD`）。
4. 若提示「输入钥匙串密码」，输入你的 Mac 登录密码。

### 2.3 转 Base64 并复制

```bash
cd ~/Desktop
base64 -i cert.p12 | tr -d '\n' | pbcopy
echo "已复制到剪贴板，长度：$(pbpaste | wc -c)"
```

> `tr -d '\n'` 去掉换行，避免某些平台粘贴时截断。剪贴板内容直接粘进 GitHub Secret 即可。

---

## 三、获取 .mobileprovision 描述文件

### 3.1 先注册设备 UDID

1. 开发者门户 → `Certificates, Identifiers & Profiles` → 左侧 **Devices** → `+`。
2. 填设备名 + **UDID**。

**怎么拿 iPhone 的 UDID**：

- Mac：连上 iPhone → 打开「访达」→ 左侧点设备 → 点顶部设备信息区，循环切换显示 型号/容量/序列号/UDID，切到 UDID 后右键拷贝。
- Windows：装 iTunes → 连上 iPhone → 点设备图标 → 点「序列号」让它切换成 UDID → 右键复制。
- 或 Xcode：`Window → Devices and Simulators` → 选中设备 → 复制 `Identifier`。

### 3.2 创建/下载 Development 描述文件

1. 门户 → **Profiles** → `+`。
2. 选 **iOS App Development** → Continue。
3. 选 **App ID**（必须与工程 Bundle ID 匹配，或使用通配符 `com.yourname.*`）。
4. 选 **证书**：勾选 §二 导出的那张 Apple Development。
5. 选 **设备**：勾选要安装的目标 iPhone。
6. 命名（例如 `ReadingApp Dev`）→ Generate → **Download**。

> 下载得到的是 `.mobileprovision` 文件。双击它会装进 Xcode，但**CI 需要的是文件本身**，所以别只在 Xcode 里用，要保留原文件。

### 3.3 转 Base64

```bash
cd ~/Downloads
base64 -i ReadingApp_Dev.mobileprovision | tr -d '\n' | pbcopy
echo "已复制，长度：$(pbpaste | wc -c)"
```

## 四、在 GitHub 配置 Secrets

1. 仓库页 → **Settings** → 左侧 `Secrets and variables` → **Actions**。
2. 点 `New repository secret`，逐个添加（名字**必须完全一致**，区分大小写）：

| Name | Secret |
| --- | --- |
| `BUILD_CERTIFICATE_BASE64` | §2.3 复制的长串 |
| `P12_PASSWORD` | §2.2 设置的密码 |
| `PROVISIONING_PROFILE_BASE64` | §3.3 复制的长串 |
| `TEAM_ID` | §1.1 的 10 位 ID |

3. 可选再添加 `BUNDLE_ID`（若你的 App ID 与工程默认 `com.example.ReadingApp` 不同）。

> **安全提醒**：p12 里含私钥，泄露等于证书被他人使用。建议为该 CI 单独生成一张开发证书，离职/换机时在门户 revoke；不要用 Distribution 证书跑 CI；Secrets 添加后无法再查看明文（只能覆盖）。

## 五、触发构建

| 方式 | 操作 | 说明 |
| --- | --- | --- |
| push main | `git push` | 自动跑，导出方式默认 `development` |
| 手动 | `Actions → CI → Run workflow` | 可在下拉里选 `development` / `ad-hoc` / `app-store-connect` |

流水线顺序：

```
Xcode 15.4 + iOS 17 校验
  → SPM 依赖缓存
  → 工程合规校验（快速失败）
  → 全量单元测试 + 覆盖率（iPhone & iPad）
  → Secrets 齐备性校验
  → 解析 Bundle ID
  → 导入证书 + 描述文件（含 Team/AppID/有效期三项一致性诊断）
  → Release Archive（手动签名）
  → 生成 ExportOptions.plist → 签名导出 IPA
  → codesign 严格校验 + 内嵌描述文件核对
  → 上传制品（IPA / dSYM / 报告，保留 30 天）
  → 清理临时钥匙串
```

任何时候失败，先看是哪一步红——签名相关问题的定位信息都在「导入签名证书与描述文件」和「Archive」两步的日志里。

## 六、下载与安装

1. 运行页最下方 `Artifacts` → **`ReadingApp-development-ipa`**（GitHub 会再包一层 zip，解压后是 `.ipa`）。
2. 文件名形如 `ReadingApp-development-0.1.0-1.ipa`。

**安装渠道**：

| 平台 | 工具 | 说明 |
| --- | --- | --- |
| Mac | **Apple Configurator 2** | 连设备 → 拖入 ipa，保留原签名，最贴合 development 包 |
| Mac | **Xcode** | `Window → Devices and Simulators` → 把 ipa 拖到设备上 |
| Windows | **iMazing / 3uTools** | 「安装 ipa」功能，保留原签名 |
| 任意 | **Sideloadly** | 会用本地账号**重新签名**，等于没用云端签名（7 天规则照旧）——仅当你不想在门户登记 UDID 时用 |

> 装不上且提示「无法安装 / 未受信任」时，先确认：设备 UDID 在描述文件里、描述文件没过期、签名 Team 与设备上信任的一致。

## 七、常见签名失败排查

### ① `errSecInternalComponent` / 构建卡在 codesign 不动

**根因**：钥匙串已锁定，或私钥未授权给 `codesign` 使用（CI 无 GUI，无法弹窗确认）。

**排查**：看导入步骤日志里 `security set-key-partition-list` 是否执行成功；确认参数含 `codesign:`。

```bash
security set-key-partition-list -S apple-tool:,apple:,codesign: -k "$KEYCHAIN_PASSWORD" "$KEYCHAIN_PATH"
security list-keychain -d user -s "$KEYCHAIN_PATH" login.keychain-db
```

工作流里两步都已内置；如你改过脚本，注意 `-S` 必须带 `codesign:`。

### ② `No signing certificate "Apple Development" found`

**根因**：钥匙串里没有可用身份。三种可能：p12 密码错（`security import` 会失败或导入空壳）、p12 里只有证书没私钥、证书已过期。

**排查**：工作流在导入后会打印 `security find-identity -v -p codesigning`，可直接看到：

- 输出里完全没有 `Apple Development` → 密码错或 p12 不完整；
- 有但标 `CSSMERR_TP_CERT_EXPIRED` → 证书过期，去门户重新生成（记得重新导出 p12 并更新 Secret）。

本地自查同理：`security find-identity -v -p codesigning`。

### ③ `Provisioning profile "xxx" doesn't include signing certificate "Apple Development: ..."`

**根因**：描述文件生成时**没有勾选**这张证书（常见于先建描述文件、后换证书）。

**修法**：门户 → Profiles → 编辑该描述文件 → 勾上新证书 → 重新下载 → 更新 `PROVISIONING_PROFILE_BASE64`。

### ④ `Provisioning profile "xxx" doesn't include the application-identifier entitlement` / Bundle ID 不匹配

**根因**：描述文件的 App ID 与工程 Bundle ID 不一致。

**排查**：工作流导入步骤会打印三行对照：

```
描述文件 App ID：A1B2C3D4E5.com.example.ReadingApp
工程 Bundle ID：com.example.ReadingApp
```

两者必须同前缀同后缀（或描述文件为通配符）。不一致时：要么加 Secret `BUNDLE_ID` 改成描述文件里的 Bundle ID，要么去门户为工程 Bundle ID 建 App ID + 描述文件。

### ⑤ `Provisioning profile "xxx" doesn't include the currently selected device`

**根因**：目标 iPhone 的 UDID 没登记进描述文件。

**修法**：门户 → Devices 添加 UDID → Profiles 编辑勾上新设备 → 重新下载 → 更新 Secret。**注意这是安装期/导出期报错，不是构建失败**——IPA 能生成，装的时候才失败。

### ⑥ `No profiles for 'com.xxx' were found`（发生在 exportArchive 阶段）

**根因**：`ExportOptions.plist` 里 `provisioningProfiles` 的键（Bundle ID）或值（描述文件名）与实际不符。

**排查**：工作流会把生成的 ExportOptions 打印到日志（`plutil -p`），核对三项：`method`、`teamID`、`provisioningProfiles`。名称必须与描述文件的 `Name` 字段**完全一致**（含空格、大小写）。

### ⑦ `The request failed because the account is not authorized` / `No Accounts with App Store Connect access`

**根因**：脚本里误加了 `-allowProvisioningUpdates`（它会尝试登录 Apple 账号）。

**修法**：手动签名 + 已安装描述文件的场景**不要**加这个参数。工作流已刻意省略。

### ⑧ 描述文件过期（最隐蔽的一类）

**症状**：昨天还能跑，今天突然在 Archive 或安装时失败。

**排查**：工作流导入步骤会打印「描述文件到期时间（UTC）」并在过期时**提前失败**。Development 描述文件默认有效期 1 年，续期后记得重新下载并更新 Secret。

### ⑨ `error: exportArchive: Nothing to export`

**根因**：Archive 里没有已签名的 `.app`（通常是 Archive 阶段签名被静默跳过，比如同时传了 `CODE_SIGNING_ALLOWED=NO`）。

**修法**：确认 Archive 步骤的参数里没有残留 `CODE_SIGNING_ALLOWED=NO` / `CODE_SIGNING_REQUIRED=NO`——签名版工作流不应出现这两个。

### ⑩ `Ambiguous identity` / 多个同名证书

**根因**：钥匙串里装了多张同名 Apple Development 证书。

**修法**：CI 用的是临时钥匙串，只导入你给的那一张，一般不会出现；本地调试时清理旧的同名证书即可。

## 八、与「未签名打包」的关系

本仓库现有**两条并行流水线**，互不干扰：

| 文件 | 名称（Actions 侧） | 触发 | 产物 |
| --- | --- | --- | --- |
| `.github/workflows/ci.yml` | `CI` | push main + 手动 | 签名版 Development IPA |
| `.github/workflows/ci-unsigned.yml` | `CI (Unsigned)` | **仅手动** | 未签名 IPA（Payload 直压） |

备用流水线的定位：当签名因证书 / 描述文件 / UDID 问题失败时，用它先拿到一个可用 IPA，用 Sideloadly 本地重签装上看效果，不阻塞其他验证工作。它刻意不挂 `push`，避免与签名版重复构建、浪费 macOS 分钟数；若希望每次 push 都同时产出未签名包，把文件里 `push:` 两行取消注释即可。

两套产物的区别：

| | 签名版（当前） | 未签名版 |
| --- | --- | --- |
| 证书 | 必须 | 不需要 |
| 产物 | Development IPA，可直接装到已登记设备 | 未签名 IPA，只能用 Sideloadly 等工具重签 |
| 有效期 | 描述文件 1 年 | 重签后 7 天 |
| 适用 | 自己/团队成员日常安装 | 分发验证、二次签名 |

另外：签名版工作流只由 `push main` 与手动触发——**PR 不再跑测试**，因为 fork PR 拿不到 Secrets。若仍想在 PR 上跑测试，新建一个只做「合规校验 + 单元测试」的工作流，不涉及签名即可。

## 九、速查：一次性把四个 Secret 准备好

```bash
# 1) 证书 -> Base64（在生成证书的那台 Mac 上）
base64 -i ~/Desktop/cert.p12 | tr -d '\n' | pbcopy
#    -> 粘贴为 BUILD_CERTIFICATE_BASE64

# 2) 描述文件 -> Base64
base64 -i ~/Downloads/ReadingApp_Dev.mobileprovision | tr -d '\n' | pbcopy
#    -> 粘贴为 PROVISIONING_PROFILE_BASE64

# 3) 本地自查（可选，确认证书与私钥配对、未过期）
security find-identity -v -p codesigning | grep "Apple Development"

# 4) 本地自查描述文件内容（可选）
security cms -D -i ~/Downloads/ReadingApp_Dev.mobileprovision > /tmp/p.plist
/usr/libexec/PlistBuddy -c "Print :Name" /tmp/p.plist
/usr/libexec/PlistBuddy -c "Print :TeamIdentifier:0" /tmp/p.plist
/usr/libexec/PlistBuddy -c "Print :Entitlements:application-identifier" /tmp/p.plist
/usr/libexec/PlistBuddy -c "Print :ExpirationDate" /tmp/p.plist
```
